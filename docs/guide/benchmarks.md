# Benchmarks

Every number on this page comes from scripts in the repository, recorded in [`bench/results/`](https://github.com/Alexis-Technologies/kerberos/tree/main/bench/results) and turned into these charts and tables by `pnpm bench:report`. They were measured on one machine (named under each chart). Treat them as relative guidance, not absolutes: the order and the orders of magnitude carry over to other hardware, the exact figures do not.

### How to read it

The libraries do different amounts of work per call, so read the chart as a price list, not a ranking:

- **CASL, @rbac/rbac and AccessControl** check an in-memory predicate or map: no policy documents, versions or scopes, no audit or telemetry path, no query planner. @rbac/rbac also memoizes role × operation lookups. Every timed call repeats the same request, so it is measured at its cache-hit speed.
- **CASL builds an ability per user.** The *built once per user* row times the check alone. The *built per request* row includes building the ability, which is what you pay unless you cache abilities between requests. With 1,000 rules that build dominates.
- **A Kerberos.js call** includes argument validation, the guarded audit, telemetry and hook seams, and the walk along the scope chain. Its rule index keeps the 1,000-rule policy as fast as the one-rule policy. casbin, OPA's WebAssembly build and per-request CASL all slow down as the policy grows.
- **OPA server and Cerbos PDP run as sidecars.** Every decision is a serialized request over localhost, so the transport dominates whatever the engine does. The numbers were taken on Docker Desktop, where the round-trip also crosses the VM's network bridge, so they are slower than on a Linux host. A network hop is never free, though, which is the cost Kerberos.js is built to avoid.

### Method

- Every (library, scenario) pair runs in a **fresh process**, so no library's JIT feedback or heap state leaks into the next one.
- Before timing, each adapter must reproduce the scenario's expected **allow and deny** decisions (and the exact set of visible ids for the list). A mismatch aborts the run.
- After a one-second warmup, calls are timed in five one-second samples and the **median** is reported. Calls run in chunks, so reading the clock does not dominate sub-microsecond calls. A library whose check returns synchronously is never awaited, because awaiting would charge it a microtask its callers do not pay.
- OPA and Cerbos run from **pinned images**: `openpolicyagent/opa:1.21.1` and `ghcr.io/cerbos/cerbos:0.55.0`, the version the conformance suite runs against. OPA is measured twice. Once its Rego is compiled to WebAssembly and evaluated in-process with the official SDK. Once it runs as a server. Cerbos is called through its gRPC SDK, the faster of its two transports, and its batch call sends all 100 documents in one request. `@cerbos/embedded` is absent: its policy bundles can only be built by Cerbos Hub.

## Kerberos.js hot paths

The zero-dependency regression harness in [`bench/bench.js`](https://github.com/Alexis-Technologies/kerberos/blob/main/bench/bench.js) covers the engine's own paths: the single check, batches, metadata, role-policy chains, scopes, validation backends, hooks and listeners, cache-backed `$expr` policies, query plans and relations. Each scenario gets up to 0.5 s of warmup, then five one-second samples, and the median is reported.

`checkResources` evaluates resources **concurrently** (`Promise.allSettled`). With a remote policy store, N resources cost one parallel wave of lookups instead of N sequential round-trips (about 8× faster with a 2 ms-latency cache and 10 resources). One failing resource never fails the batch: it fail-closes to `EFFECT_DENY` for its own actions only.

## Reproducing the numbers

```bash
node bench/bench.js --json --samples 5        # hot paths → bench/results/engine.json
git worktree add ../kerberos-previous v4.2.0  # the previous release, measured with today's harness:
node bench/bench.js scaling --json --samples 5 --src ../kerberos-previous
pnpm bench:compare                            # libraries + cold start → bench/results/compare.json (needs Docker)
node scripts/size-compare.js --json           # bundle sizes → bench/results/size.json
pnpm bench:report                             # charts (docs/public/benchmarks) + the tables on this page and in the README
```

`pnpm bench:compare --no-docker` skips OPA's server and Cerbos. `--only kerberos,casl` and `--scenarios abac,batch` re-measure a subset and merge it into the existing results. `pnpm bench:coldstart` breaks Kerberos.js's own start-up into `require`, construction and the first decision.

## Fuzzing

The security-sensitive surfaces — the `$expr` codec (parse + evaluate), the CEL translator's output contract, the YAML subset parser, and `RelationResolver` — are covered by a deterministic, seeded fuzz suite (`test/Fuzz.test.js`) that runs as part of `pnpm test` and can be cranked with `FUZZ_ITERATIONS=100000`. The properties asserted are the contracts: typed errors only, no leaked functions, no prototype pollution, and every expression the translator emits must compile.
